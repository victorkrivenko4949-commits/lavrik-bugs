# 🐞 lavrik-bugs — баги от Лаврика

Сюда Лаврик кидает ошибки (текстом, голосом, со скринами), а агент забирает их отсюда и чинит.

## Для Лаврика — как сообщить об ошибке

**Самый простой путь (с телефона или компьютера):**

1. Открой страницу https://lavrik-bugs.onrender.com/
2. Введи пароль сверху (спроси у Виктора).
3. Нажми **🎤 Рассказать голосом** и расскажи, что сломалось (или напечатай).
4. Прикрепи скриншот, если есть, и нажми **Отправить ➜**. Всё!

Аккаунт GitHub не нужен. Через минуту после отправки в баге появится ответ «Принято» — значит, дошло. Если агент задаст вопрос — на той же странице внизу появится раздел «💬 Вопросы от агента»; ответь там (с тем же паролем).

## Для владельца

- Все баги: https://github.com/victorkrivenko4949-commits/lavrik-bugs/issues?q=is%3Aissue+is%3Aopen+label%3Abug
- Автопочинка: автоматизация Perplexity каждый час читает открытые issues, сверяет с базой (только баги, прошедшие пароль), исправляет FORMYLA, коммитит `fix(lavrik #N)` в main (Render публикует), close-fixed.yml закрывает issue. Форма и ответы Лаврика защищены паролем (`BUGS_PASSWORD` в Environment на Render).

## Дублирование багов в GitHub Issues (чтобы агент их видел)

Сервер сохраняет баг в Supabase **и** создаёт issue в этом репозитории. Агент читает issues через GitHub.

Настройка на Render (сервис `lavrik-bugs` → Environment):

1. `GITHUB_TOKEN` — fine-grained токен GitHub: Settings → Developer settings → Fine-grained tokens → репозиторий `lavrik-bugs`, право **Issues: Read and write**.
2. `SUPABASE_SERVICE_KEY` — ключ `service_role` из Supabase (Project Settings → API). Нужен, чтобы сервер читал таблицу `bugs` после отключения публичной SELECT-политики.
3. `ADMIN_KEY` — любой пароль для служебных ссылок.
4. `BUGS_PASSWORD` — пароль формы Лаврика (вводится сверху). Без него сервер не принимает баги (fail closed); в `/api/config` виден только флаг `password`.
5. Сохранить → Render перезапустит сервис.

Перенести уже отправленные баги в Issues: один раз открыть в браузере
`https://<адрес-сервиса>/api/sync-issues?key=<ADMIN_KEY>` — создадутся issues для всех багов, которых ещё нет (повторный вызов дублей не делает).

Проверка: `https://<адрес-сервиса>/api/config` должен показать `"github": true`.

## Как это устроено

| Файл | Что делает |
|---|---|
| `index.html` | Страница для телефона: голосовой ввод (Web Speech API, ru-RU) → предзаполненная форма на GitHub |
| `.github/ISSUE_TEMPLATE/bug.yml` | Форма бага на русском: где, что за проблема (ошибка/дизайн/съелся текст/…), что, как повторить, ссылка, важность |
| `.github/workflows/auto-reply.yml` | Автоответ «Принято» + метка `bug` на каждый новый баг |
| `server.js` | Приём бага → Supabase → дублирование в GitHub Issues; `/api/sync-issues` переносит старые баги |
